# App da Feirinha — Plano de construção

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Um app web para iPhone que monta pedidos da feira, gera a mensagem de WhatsApp para quem cobra, permite alterar ou cancelar pedidos e mostra o resumo do dia, funcionando sem internet.

**Architecture:** Site estático, sem etapa de build, com HTML, CSS e JavaScript em módulos ES. A lógica fica em módulos puros testados com `node --test`: dinheiro e datas, produtos, pedidos, mensagens, resumo e armazenamento. As telas são funções de render em JavaScript puro, sobre um único objeto de estado salvo no `localStorage` a cada mudança. Um service worker guarda os arquivos para uso offline. A hospedagem é no GitHub Pages.

**Tech Stack:** HTML, CSS, JavaScript ES2022 sem bibliotecas; Node 24 (`node --test`) só para os testes e para o servidor local; `gh` CLI para publicar.

**Spec:** `docs/superpowers/specs/2026-11-16-feirinha-design.md`

## Global Constraints

- O app não tem dependências de npm nem etapa de build. `package.json` existe só para `"type": "module"` e para o script `test`.
- Todos os caminhos são relativos (`./js/app.js`), porque o site vai rodar em `https://<usuario>.github.io/feirinha/`.
- Dinheiro é sempre um inteiro em centavos. O texto mostrado segue o formato `R$ 1.240,00`, com espaço comum depois de `R$` e sem usar `Intl`.
- Todo o texto da interface e das mensagens é em português do Brasil.
- Formas de pagamento, nesta ordem: `credito` "Crédito", `debito` "Débito", `pix` "Pix", `dinheiro` "Dinheiro".
- As abas, nesta ordem, são: **Vender · Pedidos · Produtos · Resumo**.
- O alvo é o iPhone com Chrome (WebKit), aberto pelo ícone da tela inicial. Os botões têm no mínimo 44px de altura.
- Datas são sempre a data local do aparelho, nunca UTC.
- O estado é salvo no `localStorage` a cada mudança. Se o salvamento falhar, aparece um alerta visível.

## Review Focus

1. **Pedido feito à noite:** depois das 21h em Brasília, a data em UTC já virou o dia seguinte. O pedido precisa contar no dia local (testado na Task 1, `dateKey`).
2. **Dois toques em Enviar ou Copiar:** o pedido é registrado e numerado uma única vez (Task 3, `ensureCommitted`).
3. **Preço digitado do jeito brasileiro:** `3,50`, `R$ 3,50`, `3.50` e `3` são aceitos. Vazio, zero, negativo e texto são recusados com aviso (Task 1, `parsePriceBRL`).
4. **Gerar mensagem sem nenhum item ou sem forma de pagamento:** aparece um erro claro e nada é salvo (Task 3, `validateDraft`).
5. **Alteração inválida:** um pedido não pode ficar sem itens numa alteração, e um pedido cancelado não pode ser alterado nem cancelado de novo (Task 3, `alterOrder` e `cancelOrder`).

## Formatos de dados (referência para todas as tarefas)

```js
// Product
{ id: string, name: string, priceCents: number }
// Item (dentro de Draft e de Order)
{ productId: string, name: string, priceCents: number, qty: number }   // qty >= 1
// Draft: pedido sendo montado
{ customer: string, payment: 'credito'|'debito'|'pix'|'dinheiro'|null, items: Item[] }
// Order: pedido que já vale
{ id: string, number: number, customer: string, payment: string, items: Item[],
  createdAt: number /* ms */, status: 'ativo'|'alterado'|'cancelado',
  previousTotalCents: number|null }
// Checkout: o pedido em andamento na tela Vender/Mensagem
{ draft: Draft, orderId: string|null }   // orderId != null => já registrado
// State: o que vai para o localStorage
{ version: 1, products: Product[], orders: Order[], nextNumber: number,
  checkout: Checkout|null, editing: { orderId: string, draft: Draft }|null }
```

Todas as funções de estado são puras: recebem `state` e retornam um novo `state`, sem mutar o recebido.

- [ ] **Step 2: Tela Vender** (`js/views/vender.js`)

A tela tem o campo "Nome do cliente", a lista de produtos com `−` quantidade `+`, os 4 botões de pagamento (um selecionado por vez), o total ao vivo com `itemsTotal` e o botão **Gerar mensagem**. Cada toque atualiza `state.checkout.draft` via `ctx.update`, para que o pedido em andamento sobreviva se a tela bloquear. O **Gerar mensagem** chama `validateDraft`. Se houver erro, mostra o texto em vermelho acima do botão e não sai da tela. Se não houver erro, faz `ctx.go('mensagem')`. Se `state.checkout` for nulo, ou se já tiver `orderId` (o pedido anterior já foi registrado), a tela começa um draft novo `{customer:'', payment:null, items:[]}`. Com zero produtos cadastrados, a tela mostra "Cadastre seus produtos na aba Produtos." e um botão que leva para lá.

Com `params.editOrderId`, a mesma tela trabalha sobre `state.editing`. O título vira "Alterando #N – Nome", o botão vira **Salvar e gerar mensagem** e aparece também o botão vermelho **Cancelar pedido**. Esse modo é usado na Task 6.

- [ ] **Step 3: Tela Mensagem pronta** (`js/views/mensagem.js`)

A tela mostra `orderMessage` do draft com o número `checkout.orderId ? pedido.number : state.nextNumber`, num bloco verde parecido com o WhatsApp. Os botões são:
- **Enviar no WhatsApp:** chama `ensureCommitted` via `ctx.update` e depois `openWhatsApp`.
- **Copiar mensagem:** chama `ensureCommitted` e depois `copyText`. Mostra o toast "Mensagem copiada!", ou "Não deu para copiar. Selecione o texto e copie." se falhar.
- **Voltar e corrigir:** só aparece enquanto `orderId` for nulo. Volta para Vender com o draft intacto.
- **Novo pedido:** zera o `checkout` e volta para Vender. Se o pedido ainda não foi registrado, pergunta antes "Este pedido ainda não foi enviado. Descartar?".

Se o draft ficar inválido (o que só acontece com estado restaurado), a tela volta para Vender.

- [ ] **Step 1: Ícones**

O `tools/make-icons.ps1` usa `System.Drawing` para gerar `icon-180.png`, `icon-192.png` e `icon-512.png`: um fundo verde `#2b7a4b` com um "F" branco centralizado, em negrito. Rodar o script com `powershell -File tools/make-icons.ps1`.

- [ ] **Step 2: Manifest e metas do iOS**

O `manifest.webmanifest` tem `name` "Feirinha", `short_name` "Feirinha", `start_url` "./", `scope` "./", `display` "standalone", `background_color` "#ffffff", `theme_color` "#2b7a4b" e os ícones 192 e 512. - [ ] **Step 3: Service worker**

No `sw.js`, `const CACHE = 'feirinha-v1'` e a lista `FILES` com todos os arquivos do app (o html, o css, todos os js, o manifest e os ícones). No `install`, guarda tudo no cache e chama `skipWaiting()`. No `activate`, apaga os caches com nome diferente e chama `clients.claim()`.
